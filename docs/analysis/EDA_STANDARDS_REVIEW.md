# EDA standards review

## Scope and provenance

This review covers the local EDA implementation and its documentation, including the table
explorer, relationship map and workflow decision view. Dataset findings cited here come from the
completed local execution `372ff8010bafd0b4d802`, whose report is at
`data/eda/372ff8010bafd0b4d802/report.md`. The report is generated by `make eda` at
`data/eda/<RUN_ID>/report.md`; its aggregate summary is recorded in `docs/analysis/RESULTS.md`.
The run used synthetic organizer data and does not describe a production bank.

## Corrections made

- Changed record samples to a fail-closed field allowlist. They expose entity ID references,
  reviewed low-cardinality categories, dates bucketed to month, and a few technical flags.
- Removed free text, detailed location, personal characteristics, financial amounts and balances,
  fraud and resolution outcomes from sample rows and downloads. Newly added schema columns stay
  excluded until reviewed.
- Changed the decision view to display the current steering choice, dispute handling, and its
  feasibility evidence. The view no longer presents accounts and payments as an automatic project
  recommendation.
- Added Spanish and English labels for the workflow names, assessment dimensions, traffic-light
  states and relationship alerts.
- Updated the results document and progress log to cite the available local run ID
  `372ff8010bafd0b4d802`, and added its executive summary.

## Remaining limits

Stable ID hashes are pseudonyms, not anonymization. Keep the viewer local and do not publish the
downloaded sample as anonymous data. The EDA documents show that the current dispute workflow has
weak complaint links and incomplete outcome evidence; the team steering remains the source of the
project choice until the team explicitly changes it.

## Validation record

The Python lint, formatting, import-boundary, Bandit and mypy checks pass. Markdown lint passes.
The full repository lint and typecheck targets cannot complete in this environment because `pnpm`
is not installed. Mermaid validation is also environment-dependent and must be run with the
repository's supported Node and dependency versions.
