### `scripts/checks/check_env_keys.py` design

- Variable names come from `.env.example` (lines matching `^[A-Z][A-Z0-9_]*=`), so the example stays the single list of documented variables. Only names are parsed from it; its values are ignored.
- A variable counts as set when it is non-empty in the process environment, or non-empty in the `.env` file. The script parses `.env` itself (stdlib, handles `export`, quotes, and inline comments), and only tests each value for emptiness. It never prints, logs, or returns a value, and error messages never include file content.
- A `REQUIRED` tuple in the script names the variables that must be set now: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`, `DATA_BUCKET`, `DATA_PREFIX`, `POSTGRES_ADMIN_PASSWORD`, `POSTGRES_APP_PASSWORD`, `SESSION_SECRET`, `CSRF_SECRET`. Every other name from `.env.example` is reported as optional. The LLM keys are optional while `LLM_PROVIDER=fake`; phase 08 moves them into the required set when a live provider is selected.
- Output: one line per name, `NAME: set` or `NAME: unset`, grouped as required and optional, then a summary line. Exit 1 if any required name is unset, 0 otherwise. A missing `.env` produces a notice (`.env not found; checking the process environment only`) rather than a crash.
- Flags: `--env-file PATH` (default `.env`) and `--example PATH` (default `.env.example`), so it can be tested against temporary files.

- **Accidental secret exposure by the env check.** Mitigation: the script never formats a value into any string, the sentinel test proves it, and the real `.env` is never opened by the session.
- **Node 24 instead of 22.** Node 24 is an LTS line, but later phases may pin `engines`. Deferred to phase 01 as a backlog item.
- **Hook interpreter drift.** The hooks call `python3`, which is Homebrew Python 3.14, not the uv-managed 3.12. The guard scripts use only the standard library, so this is harmless now; phase 01 may route them through `uv run`.
